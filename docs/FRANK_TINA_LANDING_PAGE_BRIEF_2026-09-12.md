## 4. ポスターから引き継ぐデザイン

### 世界観

深いネイビーを土台に、フランクのオレンジとティナの青を組み合わせる。大きなキャラクター、筆の勢い、音の波・反復を示す曲線を使い、「物語」と「口を動かす訓練」が同時に伝わる画面にする。

ポスターを1枚の大画像として貼って完了にしない。構図をWebの横幅に組み直し、見出し・説明・ボタンはHTMLにする。ストアバッジ・QRコード・価格の入ったポスター全体を、公開前サイトの主要画像として使わない。

### ヒーローの必須構成要素

以下はポスターの「勢い」を作っている要素で、ヒーローでの再現を必須とする。省略・別モチーフへの置換をする場合は理由を報告する。

1. **筆文字ロゴ**: `poster/フランケン道場透明.png` をそのまま使う。飛沫まで含んだ完成素材なので、飛沫の別素材化や再描画は不要。ヒーローではポスター同様、フランクの下・英語見出しの上に横幅いっぱい近くで置く（PCでは最大幅約720px、スマホでは画面幅の約90%）。透過を生かし、背景素材の上に直接重ねる。`FrankenDojo` / `by KataSpeak` は画像の直下または右下にサンセリフのHTMLテキストで添え、画像内に焼き込まない。配信用には幅1600px・1000px・640px程度のWebPを生成し、`srcset`で切り替える。alt は `FrankenDojo by KataSpeak`。
2. **ループ矢印＋音波モチーフ**: フランクの頭部を囲む青いループ矢印と、口元から広がるオレンジの3本の音波弧を、ヒーローの構図として再現する。「反復」と「声」を一目で伝える中核モチーフであり、背景の飾りではなくキャラクターに重ねて配置する。SVGで作成し、PCではフランクの右側、スマホではフランクの上または下に収まるよう可変にする。動きを付ける場合は一度だけの軽いアニメーションに留め、動きの軽減設定では静止させる。
3. **大きなオレンジの英語見出し**: “Train your mouth in the Dojo of language.” を主見出しとして、ポスターと同等の存在感（ヒーロー内で最大の文字）で置く。直下に「語学は鍛える時代へ」を灰白色で従として置く。
4. **キャラクターの配置**: フランクを大きく左上、ティナを右側の小さめの位置に置くポスターの主従関係を基本にする。透過素材がない場合はポスターPDFから切り出すか、差し絵から切り抜いて使う。
5. **背景**: `poster/背景.png` をヒーローの背景に使う。地色`#181B27`はCSSの背景色として敷き、画像は下端を基準（`background-position: center bottom`）に`cover`で重ね、上部の無地部分が見出しの背後に来るようにする。画像は縦長なので、1440px級のPCでは横に引き伸ばされる。波形と流線が下端に集まっているため引き伸ばしても破綻しにくいが、ぼやけが目立つ場合は、下部の装飾帯（おおよそ下側3分の1）だけを切り出してヒーロー下端に敷き、上部はCSSの単色にする。装飾はフランクや見出しの背後で目立ちすぎないよう、必要なら不透明度を下げる。ヒーロー以外のセクションでは単色`#181B27`を基本とし、フッターやCTA帯などの要所で同じ下部装飾を再利用してよい。動きは付けない。

### 訓練カードとアイコン

- SHADOWING / REPEATING の2枚のカードは、ポスターの構成を踏襲する。暗いパネル背景、角丸、青い発光縁取り、オレンジの英大文字ラベル、太字の日本語見出し、灰色の3行説明の順で組む。
- カード右上のアイコンは、ポスターの**ネオン発光スタイル**で作る。シャドーイングは「耳＋ループ矢印＋音波」、リピーティングは「口＋音波＋一時停止」を、青とオレンジの発光線で描く。フラットな単色アイコンや汎用アイコンセットで代替しない。SVGで作成し、発光はCSSのフィルタまたはSVGフィルタで付ける。
- 発光を要所に限定する方針は維持するが、この2枚のカードとヒーローは「要所」に含める。

### 書体

- 英語の見出し・ラベル（ヒーロー主見出し、SHADOWING / REPEATING、ORIGINAL STORYなど）は、ポスターと同系統の**太い幾何学サンセリフ**を使う。Google Fontsの Poppins（Bold / ExtraBold）を第一候補とし、フォールバックに Montserrat、システムのsans-serifを指定する。
- 日本語の見出しは太めのゴシック（Noto Sans JP Bold または Zen Kaku Gothic New Bold）。本文は同系統のRegular。
- 見出しは行間を詰め、字間をわずかに絞って、ポスターの密度に近づける。本文・台詞は読みやすさを優先し、行間を広めに取る。

### 色と文字

背景色は `poster/背景.png` の実測値。その他はポスターの見た目から置いた初期値で、実画面の見え方とコントラストで調整する。ロゴ画像の実測では、筆文字の青は上端`#93C0E9`付近から下端`#3366C0`付近へのグラデーション、飛沫のオレンジは`#C97024`付近。

| 用途 | 初期値 |
|---|---|
| 背景 | `#181B27`（背景素材の実測値） |
| パネル背景 | `#141923` |
| 主CTA・フランクのアクセント | `#FFA338` |
| ティナのアクセント | `#237BFF` |
| 補助アクセント | `#8ED8FF` |

- オレンジのボタンには濃色の文字を使う。補足文も背景に埋もれないよう確認する。
- ブランドロゴは上記「ヒーローの必須構成要素」1に従い、`poster/フランケン道場透明.png` を使う。新規のロゴ作成は不要。
- 本文は上記「書体」に従う。長い台詞に筆文字を使わない。
- 青い縁取りや発光は、ヒーロー・選択状態など要所に限定する。
- スキット本文は発光を抑え、落ち着いて読める行間・本文幅を確保する。
- 波形や矢印は装飾として控えめに使い、本文の背後で常時動かさない。
- スクロールを強制する演出や音声の自動再生を入れない。動きの軽減設定にも対応する。

### 画像の扱い

ロゴと背景は `poster/` の2点を使う。まず既存のキャラクター単体・差し絵素材を確認する。キャラクターの姿や服装を別物に描き直さない。透過の単体素材が見つからない場合は、実在する差し絵を構図に組み込んで進める。

差し絵は物語の内容を読むための素材でもある。詳細ページでは全体を確認できる表示にし、一覧のトリミングは焦点位置を管理して顔を切らない。原寸PNGは制作素材として保持し、公開には必要なサイズのWebP等を生成する。

8. **FAQ・最後のCTA・フッター**
   - 無料で読める範囲、A1-01体験、マイク、Webとスマホの違い、料金・提供状況。
   - 運営・問い合わせ・既存の権利表記・利用規約等の確認済みリンクを置く。存在しないリンクや架空の利用者の声を作らない。

PCではヒーローをテキストとビジュアルの2列にできる。スマホは1列とし、最初の画面でブランド・何ができるか・主CTAが伝わるようにする。下部固定CTAを使うなら本文やブラウザ操作を覆わない。

### コース一覧

- レベル・60話という件数・コース紹介・話数順のカードを表示する。
- カードにはID、タイトル、差し絵、短い場面説明を表示する。
- ID・タイトル・場面で絞り込める軽量な検索を用意する。検索結果0件と解除操作も実装する。
- 初期HTMLに全話への通常リンクを含め、検索用JavaScriptが動かなくても閲覧できる。
- プレビューの画像未完成表示を、実際の教材画像と誤認させない。

### スキット詳細

- パンくず、ID・CEFR・原本タイトル、場面説明。
- 対応する差し絵。比率を保ち、必要なら全体を拡大表示できる。
- 英文の直下に対応する和訳。話者名は明示し、色だけで区別しない。
- ナレーション、台詞、効果音を区別する。制作用の演技タグを発話本文へ混入させない。
- 和訳は初期状態で表示し、任意で隠せる。隠してもHTML本文から訳を取り除く必要はない。
- 「この回で使う表現」を原則3点、各話固有の短い解説を配置する。
- 解説は原本と整合させ、原本のセリフ自体は書き換えない。後の話の重大な展開を先取りしない。
- 「この話を練習する」導線と、前話・次話・コース一覧へのリンク。
- A1-60→A2-01などの境界も、確認したプレイ順で接続する。
- 公開ページ内では模範音声の完全再生・チャンク再生・録音・VAD・練習ランクを実装しない。

## 6. 原本・画像からの生成設計

### 原本を維持する

確認済みの原本は4ファイル各60話、合計240話で、見出しIDは全件ユニーク。例:

```markdown
### A1-01 Beyond the Stars!
```

`id = A1-01` と `title = Beyond the Stars!` を分けて抽出する。タイトルをIDにせず、原本を240ファイルへ分割しない。サイト内に台本の手編集コピーを作らない。

本文、訳、話者、ナレーション、場面、SFXなどを型のあるデータに変換する。未知の書式や英文／和訳の対応不明は黙って省略せず、原本のファイル・見出し・行番号を添えて報告する。制作タグを外す場合は既存の変換ルールを確認し、角括弧の内容を一律削除しない。

### 画像対応表

既存のファイル名を保持し、先頭のIDで候補を抽出する。実在例:

```text
A1-01_Beyond_the_Stars.png
A1-06_I_Hate_Mondays_droopy_antennae.png
```

タイトル部分の表記一致は要求しない。対応表には、採用画像、alt（日英）、一覧の焦点位置、確認状態を保存する。例:

```json
{
  "A1-01": {
    "sourceImage": "images/A1-01_Beyond_the_Stars.png",
    "alt": {"ja": "画像を実見して記述する", "en": "Describe the actual illustration"},
    "focalPoint": {"x": 0.5, "y": 0.5},
    "reviewStatus": "pending"
  }
}
```

上記altは構造例であり、そのまま本番に出さない。画像を実見して具体的な説明を書く。

- 正本にないID、画像欠損、同じIDの複数候補、画像破損を検出する。
- 複数候補を先頭ファイルや更新日時だけで自動確定しない。明示した採用対応を保持する。
- Champion画像や衣装設定画など、スキット以外の画像は別素材として分類する。
- PNG原本は改名・上書きせず、配信用ファイルを別の出力先に生成する。

ユーザー確認では差し絵120話分が完成済み。2026-09-12の機械確認では `images/` 直下にPNG128件、ID形式に一致する121件、その他7件が存在した。ファイル存在数を完成話数と同一視せず、採用・内容確認は別管理する。下位フォルダを含む全体の監査は実装時に行う。

### 共通データとサイト用情報

- 共通: 教材ID、レベル、表示順、原本タイトル、本文、和訳、話者、場面、採用画像。
- サイト用: 固定slug、ページ見出し、description、学習表現、解説、alt、焦点位置、公開確認状態。
- 音声時刻・チャンク境界など訓練専用データはアプリ側との契約に従う。公開サイトを作るために未検証の時刻を推測しない。
- 原本由来の共通データは生成物。解説などは教材IDで管理する編集用ファイルに保存する。
- `A1-01`等の配信後IDは固定。タイトル変更・表示順変更でIDを振り直さない。
- URLのslugは初回決定後に保存し、毎回タイトルから再生成しない。変更が必要なら旧URLのリダイレクトを設ける。
- 生成データに形式バージョンと教材リビジョンを持たせ、同じ原本から同じ出力を再生成できるようにする。

## 7. 訓練アプリとの接続と公開状態

ログイン・契約判定・決済・学習進捗はFrankenDojoの訓練アプリ側（既存の`saydojo_codex`ディレクトリ）で扱う。公開サイトにFirebase認証やRevenueCatの購入処理を重複実装しない。公開側は教材ID付きリンクを作る。

リンク生成は1か所へ集約する。例として `/app/lessons/A1-01` のような経路を想定できるが、これは**未確定の接続例**。実装済みのルートとして扱わず、アプリ側と合意した形式を設定する。ログインや購入後に同じ話へ戻す処理はアプリ側の要件として引き渡す。

| 状態 | 公開サイトでの扱い |
|---|---|
| Web訓練未公開 | 「アプリの公開案内」へ。壊れた `/app/` リンクを出さない |
| Web訓練公開・A1-01 | 「この話を無料で練習する」から体験へ |
| Web訓練公開・その他 | 「この話を練習する」から該当話へ。契約判定はアプリで行う |
| ストア未公開・URL未確認 | ダウンロードバッジや「今すぐダウンロード」を出さない |
| ストア公開・URL確認済み | 対応する公式バッジと実リンクを表示する |

公開状態は、サイト本番可否・Web訓練・iOS・Android・課金の状態を独立した設定で扱う。単一の「公開済み」で全部を有効にしない。

先行案内の送信先が未設定なら、ローカルではフォームの構成をプレビューできるようにし、送信成功を偽装しない。メールアドレスをコンソールやダミーストレージへ保存しない。本番の登録導線は実際の受付先、同意表示、成功・失敗処理が接続されてから有効にする。

コピーには「AIが発音を採点」「正しく言えるまで判定」「必ず話せる」「14日で習得」など未実装機能や成果保証を入れない。音声の存在・時間を使う発話検知を、内容理解や発音評価と混同しない。

## 9. 実装・検証要件

- 既存の生成ツールと依存関係を調査し、利用できるものを優先する。選ぶ静的サイト生成方式と理由をREADMEへ簡潔に記録する。
- `website/` を独立して開発・ビルドできるようにする。制作ツール・原本・音声処理を無関係に作り直さない。
- 240話はテンプレートから生成し、240個の手書きHTMLを管理しない。
- 初期HTMLに本文・見出し・内部リンクを含める。JavaScriptは検索・訳の表示切替等に限定する。
- 各ページに固有のtitle・description・canonical・OG情報を持たせる。全話を同じ説明文にしない。
- 本番URLの設定に基づくXMLサイトマップ・画像サイトマップを生成する。
- 構造化データは仕様9.4に沿って、確認できる運営情報・パンくず等を出力する。公開前アプリの架空のレビュー・評価・販売情報を追加しない。
- ステージング・プレビューはnoindex。本番インデックス対象へ未完成ページを混ぜない。
- ヒーロー画像は適切なサイズで優先取得し、下方の画像は遅延読み込み。画像の幅・高さを指定し、レイアウトのずれを抑える。
- キーボード操作、フォーカス可視化、見出し階層、ボタン名、フォームラベル、本文・CTAのコントラストを確認する。
- 390px前後のスマホ、768px前後、1440px前後で表示を確認する。320px幅でも横にはみ出さない。
- 公開対象の出力に原本PNG、制作メモ、音声原本、認証情報を含めない。

### 必要なチェック

1. 4ファイル各60話・240ユニークID・期待するID集合との一致。
2. 全話の本文・和訳・話者・場面の抽出結果。パース警告は明示して残す。
3. 採用画像の対応、欠損、重複候補、参照切れ。
4. slug・URL重複、前後話リンク、コース境界、存在しない内部リンク。
5. 240話の初期HTMLに英文・和訳が入っていること。
6. 公開状態ごとのCTA、未設定URL、先行案内フォームの成功・失敗表示。
7. トップ、キャラクター、コース一覧、スキット詳細のPC・スマホのスクリーンショット。
8. 開発時のビルド成功とブラウザ上の主要操作。実施できないチェックは完了扱いにしない。
9. ロゴ・本文・title・OG・構造化データ・画像の代替テキストに旧称SayDojoが残っていないこと。ブランド付記が`by KataSpeak`の正確な表記になっていること。
10. ヒーローの必須構成要素（`poster/`のロゴ画像と背景画像、ループ矢印＋音波、オレンジの英語主見出し、キャラクター配置）、訓練カードのネオンアイコン、指定書体が実装されていること。ロゴ画像のaltが`FrankenDojo by KataSpeak`であること。暫定表示のまま残る要素は未完了一覧に記載する。

## 10. 実装順序と完了条件

1. 原本と画像の棚卸し、対応表・欠損レポートを作る。
2. 共通の教材データ生成とサイト用メタデータの形式を定める。
3. A1-01など画像がある話を使って、LP・一覧・詳細・スマホ表示を実装する。
4. 同じテンプレートで全240話を生成し、未完成素材はローカル専用の明示的な代替表示にする。
5. 公開状態ごとの導線を接続し、データ・リンク・画面を検証する。
6. README、生成コマンド、検証結果、未完了素材と接続設定の一覧を残す。

**ローカル実装の完了条件:** 主要ページが動作し、原本から240話を再生成でき、画像・解説・接続先の未完了箇所が一覧で分かること。

**正式公開の条件:** 全240話の採用画像・本文・対訳・各話解説・学習表現の確認を終え、全ページが完成し、先行案内等の有効な導線が接続されていること。公開用ビルドには厳格な検証を設け、欠損や未確認状態を検出したら公開可能として成功させない。ローカル実装完成を正式公開可能と同一視しない。

全240話を一括公開する既存方針を維持する。内部確認のための少数話プレビューは可能だが、120話だけの正式公開へ勝手に変更しない。公開サイトはアプリ完成前にも公開でき、その場合は訓練・ストアへのCTAを先行案内へ切り替える。
